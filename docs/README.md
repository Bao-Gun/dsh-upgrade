# docs

这个目录放描述项目的文字，不放代码。

## 命名分两种

- **固定名**：骨架自带、或一个项目只需要一份的（`architecture.md`、`gotchas.md`、`design.md`）。不加日期。
- **日期名**：其余全部 `YYYY-MM-DD-主题.md`，日期是写的那天。

## 新增任何文件，同批做一件事

在 `AGENTS.md` 的「目录地图」里加一行（放什么、不放什么）。加不进地图的文件，下一个人就不会知道它存在。

## 和 superpowers 目录怎么分工

装了 superpowers 的项目会多出两处，别让它们和本目录抢同一件事：

- `docs/superpowers/plans/`、`docs/superpowers/specs/` 是**流程留下的原件**：计划与设计当时的样子，写完不再改，当历史读。
- 本目录的 `architecture.md` 是**现在的事实**：功能收尾时把还成立的部分搬过来。
- 两边打架，以 `architecture.md` 为准，再回计划里看是哪一步变了。
- `.superpowers/` 是执行工作台（进度、简报、评审包），自动忽略，不进版本库，也不要手写。

## 两类文件的寿命

- `design.md` 是**还没有代码时的纸面设计**。代码落地后，把还成立的部分搬进 `architecture.md`，然后删掉 `design.md`——两份都写系统长什么样，迟早互相过期。
- 一份文档只描述一件事。发现两份在说同一件事，删一份，别维护两份。
